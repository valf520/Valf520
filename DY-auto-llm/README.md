# 抖音私信 AI 接待

**读对话 · 大模型生成 · 六道校验 · 逐字输入 · 自动发送**

一个跑在浏览器里的抖音网页版私信助手。不是话术群发器 —— 它会先读懂对方说了什么，再决定怎么回。

## 这是什么

抖音网页版的私信，一条一条手打太累，用现成的"话术机器人"又只会复读。这个扩展的做法是：

1. **读** —— 打开会话，把最近的对话（含头像、图片、语音标记、系统提示）解析成结构化消息
2. **想** —— 连同长期记忆、本地知识库检索结果一起交给大模型，生成一句该说的话
3. **卡** —— 六道闸门过滤：空话、越界承诺、要联系方式、超长、转人工、发错内容
4. **发** —— 逐字 `insertText`（不是 `innerText =`，富文本编辑器才认），写完校验，再点发送
5. **记** —— 对话落进 IndexedDB，攒够 40 条自动压成摘要，下次接着聊

默认**草稿模式**：只生成不发。你确认过质量再关掉。

## 特性

| 能力 | 说明 |
|---|---|
| 🧠 上下文回复 | 读整段对话再生成，不是关键词匹配 |
| ⏸️ 人类停顿 | 生成完先停 8-30 秒再发，停顿期间对方再发就合并重答 |
| 🧵 连发合并 | 对方连发几条，读完一起回一条，不一条一条答 |
| 🗂️ 长期记忆 | IndexedDB 存全量对话，超过 40 条自动压缩成摘要 + 关键事实 |
| 📚 本地资料库 | 内置 277 个知识块 + 15 条路由的检索（词频 + 口语别名扩展 + 小节展开），零成本、可离线 |
| 🎙️ 语音转写 | 可选接入 OpenAI 兼容的 `/audio/transcriptions`，把语音变成文字再回复 |
| 🖼️ 图片识别 | 可选接入兼容的视觉模型，把图片变成一句描述 |
| 🛡️ 六道闸门 | 空话 / 越界承诺 / 联系方式 / 超长 / 转人工 / 发送前内容校验 |
| 🔍 自带诊断 | 面板内置探针、prompt 查看、日志、扫描未读 —— 出问题不用开 DevTools |
| 👥 群聊过滤 | 列表层看名字、会话层看「对方头像是否多个」，群聊不掺和 |
| ⏱️ 速率控制 | 每条 5-9 秒间隔、单会话每小时上限、全局令牌桶 |
| 🎯 白名单 | 只对指定会话生效，上线先拿小号试 |

## 工作流程

```
每 2.5-4 秒扫一次会话列表
      │
      ├─ 有未读？──否──▶ 等下一轮
      │        │是
      │        ▼
      │   不是群聊？──否──▶ 跳过
      │        │是
      │        ▼
      │   点进会话 → 解析消息（排序 / 方向 / 过滤系统提示）
      │        │
      │        ▼
      │   拼 prompt ＝ 人设 + 硬性红线 + 知识库 + 检索到的资料 + 长期记忆 + 最近 16 条
      │        │
      │        ▼
      │   调模型 → 六道闸门 → 草稿模式？──是──▶ 只写面板
      │        │否
      │        ▼
      │   逐字输入 → 校验内容 → 点发送 → 确认输入框已清空
      │        │
      │        ▼
      └─ 落库 + 记账 → 点返回 → 下一个会话
```

## 快速开始

### 1. 装扩展

**Edge（可以命令行直接带着扩展启动）**

```bat
start-edge.bat
```

它会用独立配置目录启动 Edge、自动加载本扩展、打开抖音。第一次需要在窗口里登录。

**Chrome（Chromium 137+ 已禁用 `--load-extension`，只能手动装一次）**

1. 打开 `chrome://extensions`
2. 右上角开「开发者模式」
3. 点「加载已解压的扩展程序」，选本目录
4. 打开并登录 <https://www.douyin.com>

> 实测环境：Windows 11 + Edge 125 + Chrome 156。

### 2. 配置

点工具栏上的扩展图标：

| 字段 | 说明 |
|---|---|
| **API Key** | 大模型服务的 Key（默认接 DeepSeek） |
| Base URL / 模型 | 任何 OpenAI 兼容接口都行：`https://api.deepseek.com` + `deepseek-chat` |
| **客服身份** | 决定说话口吻，比如「28 岁在深圳做程序员，话不多但真诚」 |
| **知识库** | 关于你/你店铺的事实，一行一条。留空则模型不会假装有产品 |
| 字数上限 / 兜底话术 | 单条回复长度；生成被拦时发什么 |
| 草稿模式 | 默认开。只生成不发送 |

保存后 **刷新抖音页面**（内容脚本只在页面加载时注入）。

### 3. 先跑草稿

打开私信、点开一个会话，面板上点：

- **「试跑一次」** —— 生成一条草稿，不发
- **「看这次送给模型的内容」** —— 确认 prompt 里有没有对话、记忆、资料

满意了再去弹窗关掉「草稿模式」，回面板点「启用」。

## 面板按钮

这个项目一半的价值在"能自己诊断"，因为抖音前端随时会改版。

| 按钮 | 干什么 |
|---|---|
| 启用 / 停用 | 开关自动扫描（状态会持久化） |
| 试跑一次 | 对当前打开的会话手动跑一轮 |
| 探测当前会话 | 输出对话容器、每行方向、解析结果 —— 选择器失效时第一个该点的 |
| 看这次送给模型的内容 | 完整 prompt，含 system 与所有历史 |
| 扫描未读 | 会话列表项数 + 每一项的未读状态 + ID |
| 看日志 | 最近 60 行内部日志（带时间戳） |
| 重置卡住状态 | 清掉 `busy` 锁，不用重启浏览器 |
| 清空当前会话的记忆 | 删掉这个会话的 IndexedDB 记录 |

## 几个关键设计

**为什么不用 `innerText = 文案` 写输入框**
抖音的输入框是富文本（React + 自定义编辑器）。直接改 `innerText` 只动 DOM，不动框架里的 model，发送按钮还是灰的 —— 这正是原版"看起来写进去了但发不出去"的原因。用 `document.execCommand('insertText')` 逐字写入才会走浏览器的编辑管线。

**为什么去重要按"会话 + 消息"而不是按话术**
按话术文本去重会导致：给 A 发过一句话，30 秒内 B 的消息也被当成"重复"跳过 —— 但会话已经被点开，消息变成已读却没回复。这是最伤用户的设计。

**为什么记忆用 IndexedDB 而不是 SQLite**
浏览器里没有原生 SQLite；WASM 版要 1.5 MB，OPFS 同步句柄在 MV3 service worker 里拿不到。IndexedDB 原生可用、事务原子、配额够用。要 SQL 就导出 JSON 再灌进 SQLite。

**为什么资料库用词频检索而不是向量**
语料 378 KB / 277 块，装进扩展就能跑，零成本零网络。向量检索要么每条消息调一次 embedding（要钱），要么塞几十 MB 的模型。这个量级词频够用 —— 再叠上「路由表优先 + 小节展开 + 目录/表格降权」，命中质量已经能看。它只能匹配字面，换个说法就未必命中，这是它的天花板。

细节都在 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 已知限制

- **选择器会随抖音改版失效。** 这是这类工具的通病，所以面板做了一堆探针；失效时改 `content.js` 顶部的 `SEL` 一处即可。
- **`event.isTrusted` 永远是 `false`。** 合成事件和真人点击在浏览器里可区分，风控想查就能查。这是整个方案的天花板，改不掉。
- **未读徽章的识别是猜的。** 靠红色圆形徽章的尺寸和颜色判断，抖音换样式就可能失效。
- **语音转写依赖页面里有可读的 `<audio>`。** 自绘播放器就没有音频地址，只能退化成"请对方发文字"。
- **只能在前台页面工作。** 标签页切到后台（`visibilityState === 'hidden'`）会主动停。
- **只在 Windows + Edge/Chrome 上验证过。**

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板不出现 | 内容脚本没注入 | 必须是 `*.douyin.com`，刷新页面 |
| 点按钮没反应 | 早期版本的 MV3 CSP 问题 | 确认 `popup.js` 存在且被 `popup.html` 引用 |
| `读不到对话内容` | 消息区选择器失效 | 点「探测当前会话」，照报告改 `SEL.thread` |
| `⛔ 不在白名单里` | 开了白名单 | 弹窗「高级」清空保存 |
| `❌ 输入框内容不一致` | 编辑器塞了零宽字符 | 已做容错；仍失败就把面板显示的 `U+XXXX` 差异发 issue |
| `拦截[CONTACT]` | 模型想发联系方式 | 正常拦截；确实要给就写进知识库 |
