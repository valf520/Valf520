# 实现细节

这份文档写给想改代码的人。用户手册看 [README](../README.md)。

---

## 1. 调度与状态机

`content.js` 只有一个异步状态机，入口是 `tick(manual)`：

```
tick()
  ├─ S.busy ? 直接返回（同步闩，await 之前就置位，防止 1s 轮询并发穿透）
  ├─ document.visibilityState === 'hidden' ? 停（后台标签页不跑）
  ├─ 距上次发送 < rand(minGapMs) ? 等
  ├─ manual ?  对「当前打开的会话」跑
  │            读不到就明说，绝不替你点开别人的会话（那会把消息变已读）
  └─ 自动 ?    picker() 从会话列表里挑一个 → handleChat()
```

`schedule()` 用 `setTimeout` 串起来，间隔 `rand(2500, 4000)`，不是 `setInterval` —— 避免上一轮还没结束就叠下一轮。

**看门狗**：`tick` 里挂一个 25 秒定时器，到点还没结束就把「当前阶段 + 最近日志」打到面板。阶段由 `stage()` 维护。

**跨标签页互斥**：`navigator.locks.request('dy-ai-send', { ifAvailable: true })`。同一账号开两个标签页时只有一个能发。

## 2. 读对话

### 2.1 找容器 `threadRoot()`

三级降级：

1. 弹窗里手填的 `THREAD_SEL`
2. 内置候选 `SEL.thread`（抖音 IM 是 BEM 拼接：`messageMessageListwrapper` / `conversationMessage...`）
3. 结构兜底：从输入框往上爬 6 层，找「在输入框上方 + 可滚动 + 有文字 + 子节点多」的兄弟块

两个排除器：

- `isSidebar(el)` —— 左侧会话列表不是消息区（`componentsLeftPanel-boxList` / `ConversationList`）
- `looksLikeList(rows)` —— 一半以上的行带日期（`09/26`、`昨天`）就是列表，不是聊天记录

### 2.2 拆行 `readThread()`

容器有时套两层 wrapper，`threadRows()` 会往下钻（最多 3 层，判据：只有一个子元素且它的 `textContent > 200` 字）。

每行的处理顺序很关键：

```
1. 剥行首日期  "09/25 没有啊" -> "没有啊"
2. 纯日期行直接丢
3. 剥行尾回执  "…打醒了 已读" -> "…打醒了"
4. 系统提示丢  "已连续互聊3天，点亮聊天火花" / "你撤回了一条消息"
5. 有文字 -> kind=text（哪怕行里有头像 <img>）
6. 没文字 -> 才判媒体（voice / emoji / image / video）
```

第 5 条是踩过的坑：每个消息行都挂 48px 头像，早期版本把「有头像的行」全判成 `emoji`。

### 2.3 方向 `dirOf()`

优先级：

1. 类名带 `isFromMe` → `me`（抖音把方向直接写在类名里，最可靠）
2. 其它类名提示 `self|mine|right|owner`
3. 几何：气泡中心的 x 与容器中线比较

### 2.4 排序

抖音的消息列表是 **`column-reverse`**：DOM 第一个元素是最新的、长在屏幕最下面。
用「首行与末行的 `top`」判断：首行 top 更大 → DOM 倒序 → 翻转数组。不翻的话 `lastIncoming()` 拿到的是最旧那条。

### 2.5 媒体降维

模型只吃文本，所以非文字消息统一变成注解：

| DOM | 注解 |
|---|---|
| 语音 `<audio>` | 配了 ASR → `[语音转写：xxx]`；否则 `[语音]` |
| 图片 `<img> > 56px` | 配了 VLM → `[图片：白色碎花裙]`；否则 `[图片]` |
| 表情 `alt="[微笑]"` | 直接用 alt，没有就 `[表情]` |
| `<video>` | `[视频]` |

`contentImg()` 会跳过 ≤56px 的小方图 —— 那是头像，不是消息内容。

## 3. Prompt 组装

```js
[
  system: 人设 + 对话状态 + (事实边界 | 边界) + 硬性红线 + 输出格式 + 非文字消息说明
          + 知识库（有就拼，没有就换一套"你没有店"的规则）
          + 参考资料（检索命中时才有）
  system: 长期记忆（摘要 + 事实 + 往来条数）
  user/assistant: 最近 ≤16 条，倒着取直到 3000 字预算用完
  （必要时补一条 user 兜底："请给出你要说的下一句"）
]
```

记忆和资料都塞在 **system**，不占对话轮次，也不污染角色交替。

`maxChars` 是硬约束写进 prompt，同时也是截断阈值（见下）。

## 4. 输出校验（六道闸门）

`sanitize(raw)`：

| 闸门 | 触发 | 结果 |
|---|---|---|
| EMPTY | 空 | 兜底话术 |
| ESCALATE | `[[ESCALATE]]` / "转人工" | 不发，面板标注 |
| CONTACT | 网址/微信/vx/QQ/电话，且知识库里没有 | 兜底话术 |
| PROMISE | 保证/百分百/无效退款/全网最低，且知识库里没有 | 兜底话术 |
| TOO_LONG | 超过 `maxChars × 4` | 兜底话术 |
| 截断 | 超过 `maxChars` | 标点处切断 + `…` |

发送前还有一道 **内容校验**（见下），所以闸门不是唯一防线。

## 5. 写入与发送

```js
await typeInto(editor, reply)      // 逐字 insertText，每字 40-110ms
if (!sameText(readEditor(editor), reply)) 放弃
click(sendButton())
if (输入框还是原内容) 再点一次 → 还不行就判失败
```

**为什么不用 `innerText =`**：只改 DOM，不动编辑器的内部 model，发送按钮仍是禁用态。

**为什么校验要容错**：富文本编辑器会塞零宽字符（`\u200b`）、不换行空格、`<br>`。`sameText()` 的做法是「去零宽 → 折叠空白 → 去标点」再比，允许一方包含另一方。严格 `===` 会让你明明看见内容却发不出去。

## 6. 长期记忆

### schema

```
chats  { id, firstSeen, lastSeen, count, summary, facts[], summarizedUpTo }
msgs   { id(auto), chatId, role:'me'|'them', kind, text, ts, archived }
       index byChat = [chatId, ts]
```

跑在 service worker 里（扩展源），页面脚本读不到。

### 写入去重

页面每次进会话都会重读同一段 DOM。`appendMsgsDedup()` 用「新列表的后缀」去撞「已存尾部的后缀」，撞上的部分视为已存在，只写新消息。判据是 `role|text`，最长匹配优先。

### 压缩

未归档消息 > 40 条时，把最老的 `n-20` 条交给模型压成：

```json
{ "summary": "200 字摘要", "facts": ["客户要 M 码", "在意发货速度"] }
```

原文标 `archived`，不再进 prompt。压缩在后台跑，不阻塞回复。

### 会话 ID

优先级：URL 的 `/user/(\d+)` → 气泡里的 `/user/` 链接 → 会话头部（昵称算 hash）→ 首条消息 hash。
拿不到真实 ID 时用 `name-xxx` / `item-xxx` / `open-xxx` 三种兜底，保证记忆不会因为拿不到 ID 而丢。

## 7. 本地资料库

### 构建

`tools/build-kb.mjs` 把上游仓库的 Markdown 按 `##` 切块，>1000 字再按行切，<80 字的碎块丢掉。
同时从 `SKILL.md` 的「按需加载」表抽出**路由表**：

```
44 个 md → 277 块 / 378 KB + 15 条路由（kb/routes.json）
```

每个块带 `doc`（文档名）、`path`（knowledge/practical/core）、`sec`（小节）、`idx`（文档内序号）、`kind`（text/table）。

### 检索

`kb/retrieve.js`，tf-idf 余弦，四层加强：

| 机制 | 作用 |
|---|---|
| 单字 + 双字混切 | 单字保召回（"吵/架"对得上"冲突"），双字保精度；虚词单字丢弃 |
| 口语别名（14 组） | `没回 / 不理我 → 冷淡 + 投入 + 回复`、`表白 → 主动表达` |
| **路由优先 ×1.8** | 查询命中路由表关键词 → 该文档所有块加权。"刚吵完架"直接进《沟通、冲突与修复》 |
| **小节展开** | 命中一块后，把同一 `file+sec` 的相邻块拼起来（≤1200 字）再给模型，避免论证被块边界切断 |

三层降权，压住"跟什么都沾边"的块：

| 类型 | 系数 | 原因 |
|---|---|---|
| 表格块 | ×0.6 | 表格词分布散，容易误命中（曾经一张表占 900 字却没用） |
| `core`（SKILL.md） | ×0.55 | 操作手册，和任何话题都有词面重叠 |
| 目录/索引/书单/参考文献 | ×0.5 | 词很全但没有内容 |

实测（`kb-test7.mjs`）：

```
她三天没回我消息  → 《关系投入校准》/定位与证据边界 + 四、可直接改写的话术
刚吵完架，怎么修复 → 《沟通、冲突与修复》/一、目标不是零冲突 + 六、修复的构成
她说压力大不想谈恋爱 → 《依恋理论与情绪调节》/六、标签的禁用方式 + 四、对焦虑方的建议
1+1 等于几 / 你课程多少钱 → 闸门直接跳过，不查
```

### 常驻内容

安全与红线不靠检索，直接写死进 system：

- 自伤/暴力/跟踪 → 先保安全 + 报警 + `[[ESCALATE]]`
- 不诊断心理疾病、不贴 MBTI/依恋标签
- 不保证效果；对方明确拒绝就停
- 不下药/偷拍/跟踪/勒索
- 证据分强弱：经验策略用"一般/多数时候"，不说成"一定"

### 已知边界

词面匹配，不是语义匹配。别名表没覆盖的说法会漏 —— 这是刻意的取舍，向量检索要每条消息一次网络调用。

## 9. 性能与成本

- 每轮扫描：会话列表项 + 消息行，O(会话数 + 消息数)
- 每轮生成：≈1500 输入 token + 60 输出 token（含记忆与 900 字资料）
- 压缩：每 40 条一次额外调用
- 语音转写：按分钟计费，取决于服务商
- 检索：本地 CPU，277 块索引 < 5ms

省钱的三个旋钮：`KB` 别超过 1500 字、system prompt 别塞动态内容（吃缓存）、`maxChars` 别太大。

## 10. 排错方法论

这类工具 90% 的故障是**选择器失效**，所以面板做了一排探针：

| 探针 | 回答什么问题 |
|---|---|
| 探测当前会话 | 容器是谁、每行方向对不对、解析出几条 |
| 扫描未读 | 列表项识别到几个、谁有未读、ID 是什么 |
| 看这次送给模型的内容 | 上下文有没有断、记忆有没有接上 |
| 看日志 | 卡在哪个阶段、失败在哪一步 |

改选择器只改 `content.js` 顶部的 `SEL` 一处，不要散落在逻辑里。
